Components

Notice

The system's one message component — sign-in errors, destructive plan warnings, drift, failed applies, daemon disconnects. Shaped as a printed ledger entry rather than a card: the machine's classification and error code sit in a mono gutter, the human sentence in sans beside it. That is the system's existing rule made structural — mono is a literal value, sans is language about it — and it means the error code is always present rather than an optional afterthought, which matters when the next move is pasting it to an agent.

Severities — stacked as a group
failed apply.step_failed
Applying pln_8fkq2 stopped at step 3 of 6 — jerry never became healthy.
Three changes were applied before the failure and can be reverted.
drifted resource.drift
2 labels on caddy-edge changed outside cockpit.
pending plan.awaiting_approval
claude-code proposed a plan updating 3 resources on prod-fsn1.
disconnected daemon.no_contact
No contact from lab-nbg1 for 3 days.

Severity tints exactly two things: the rule and the tag. Never the body, never a background. A neutral notice takes no colour at all.

Narrow containers — stacked variant
failed oauth.access_denied
The authorization was cancelled or expired.

Auth panels, side rails, and drawers collapse the gutter above the message rather than squeezing it. The rule and tag survive, so it still reads as the same object. In the implementation this should be a container query, not a modifier class — the component should adapt to its container without the caller knowing.

Stamp

A solid classification chip. Not a notice — a stamp labels a thing, a notice says a sentence. Its home is Plan impact, where the entire point is that severity is a typed field the system cannot forget to show. Solid fill lets it survive being one small element in a dense diff.

Plan impact
none reload restart replace destructive

Only the two impacts that can hurt you take colour. none and reload are outlined, restart is solid ink — so a plan full of harmless changes carries no colour at all, and one destructive change is unmissable.

In a plan diff
resource.update res_jerry
restart Set LOG_LEVEL to debug
info → debug
resource.delete res_old_cache
destructive Remove redis-cache and its volume
irreversible — 2.1 GB of data is lost

Button

Four variants, three sizes. Emphasis comes from contrast, not colour — the primary action is solid ink, never a brand colour. Danger is the single exception and is reserved for actions that destroy something; using it to mean "important" is what makes it stop registering in the one place it matters.

Variants

primary solid ink, one per screen — if there are two, one of them is not primary. ghost the default for everything else. quiet borderless, for dense contexts like table rows where a border on every item would out-weigh the data beside it. danger solid, because a destructive action should look as committed as it is; outlining it reads as a warning rather than a decision.

Sizes
With icon, icon-only, and states

Empty state

One component for every "nothing here yet" screen — no servers, no plans, no activity, no releases, no logs, a filter that matched nothing. The anatomy is fixed so they all read as the same object: art (optional), title stating what is absent, body of one sentence on what to do, actions with exactly one primary, and an optional extra slot for the thing you would otherwise have to go and find.

Full — page level

No servers yet

cockpit doesn't create machines — you bring a box you already own. Run one line on it and it enrols itself, with no SSH access handed over.

Illustrations follow one rule, so they generate rather than get invented: solid hairline is what exists, dashed is what is absent. Here the rack is real and the bays are empty. No servers becomes an empty rack; no plans becomes a ledger with dashed rows; no activity becomes a flat trace. Flat elevations, never isometric — blueprint drawing sits closer to paper-and-ink, and soft tinted isometric spot art is the house style of every other platform's empty state.

With extra — when the action needs a command

Waiting for the daemon

Run this on the box. It hardens the host, installs Docker and cockpitd, and enrols automatically.

Terminal
$ curl -fsSL https://cockpit.oflabs.dev/install.sh | sh -s -- --token ck_enrol_8fkq2t

The extra slot exists so an empty state can carry the thing you would otherwise navigate away to find. Here the enrolment command is the entire action, so putting it behind a button would be ceremony.

Inline — an empty region inside a populated screen

Nothing deployed on this server

Apps, databases, and cron jobs you add will appear here.

No illustration and smaller type: it is a gap in a page, not a page. Using the full variant here would make an empty section shout louder than the populated ones around it.

Terminal

A copy-paste command block — enrolment, exec, migrations, anywhere cockpit asks you to run something. Copy takes the command only: prompts, comments, and sample output are marked so they never reach the clipboard.

Default — structural highlighting
Terminal
$ curl -fsSL https://cockpit.oflabs.dev/install.sh | sh -s -- --token ck_enrol_8fkq2t

Highlighted by weight and ink alpha rather than hue. Every other colour in cockpit means a state — healthy, pending, drifted, failed — so a purple keyword and a blue string would be the only colours in the product that mean nothing. The command sits at full ink because it is what you are being asked to run; flags and values are qualification. A dashed underline marks a value you must substitute, which needs no legend.

Multi-line, with output
Exec — jerry
# run inside the container $ pnpm migrate:deploy 4 migrations applied in 812ms $ cockpit logs --follow jerry
Tinted variant — for comparison
Terminal
$ curl -fsSL https://cockpit.oflabs.dev/install.sh | sh -s -- --token ck_enrol_8fkq2t

The same block using the semantic accents as syntax colours. It reads fine in isolation, but it spends green, blue, and amber on tokens that carry no state — and those three colours are what a failing container, a pending plan, and drift are supposed to own.

Considered and rejected

The first attempt was a bordered box with a coloured left stripe and a coloured dot. That is the shape every UI converges on by default, so it reads as generic, and it spreads colour across three elements instead of concentrating it.

Two alternatives were built and dropped. Tape — hairlines top and bottom, no sides — read as a clean instrument readout but was too quiet to carry a failed deploy. Hatch replaced the solid stripe with hazard tape; it was the most physical of the options, but hatching is a strong mannerism that would appear on every screen and tire quickly. Stamp was not rejected — it was promoted to its own component above, where a compact solid chip is the right answer.
